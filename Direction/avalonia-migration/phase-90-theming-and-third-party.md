# Phase 90 — Theming, icons, and third-party WPF library replacement

## Purpose

Give the Avalonia head the tool's look: the FRB light/dark themes, accent colors, app scaling, the
icon set, custom window chrome, and the controls that today come from WPF-only packages. Replace
each WPF-only third-party dependency with an Avalonia-native equivalent or drop it.

## Builds on

- Theming is already service-shaped: `IThemingService` (headless), `ThemingDialogViewModel`
  (headless, #3794), `IAppScaleProvider` / `UiSettingsService` (#3811), a theme preview under the
  theme dropdown (#4655).
- `Gum/Themes/` holds 15 resource dictionaries: `Frb.Brushes.{Light,Dark}`, `Frb.Accents`,
  `Frb.Styles*`, `Frb.Buttons`, `Frb.TreeView`, `Frb.Theming`, `Frb.Converters`,
  `MainPanelControl.Styles`, and `GumIcons.xaml` (generated by `GumFigmaIconRipper`, with
  `GumIconKind.g.cs`).
- `Frb.Styles.Defaults.xaml` derives from `MaterialDesignThemes` styles; 9 XAML files use the
  `materialDesign:` namespace.

## Decisions

- **Map light/dark to Avalonia `ThemeVariant` + `ResourceDictionary.ThemeDictionaries`.** WPF
  `DynamicResource` brushes map one-to-one. The FRB palette is ported by hand; the Avalonia
  `IThemingService` implementation switches `RequestedThemeVariant` and accent resources.
- **Rebuild the style base on Avalonia's Fluent theme, not on a MaterialDesign port.** Gum's
  styles `BasedOn` MaterialDesign today; there is no drop-in Avalonia MaterialDesign. The FRB look
  is Gum's own brushes and metrics, so re-basing on Fluent and re-applying the FRB dictionaries is
  the honest port.
- **Script-convert `GumIcons.xaml`.** It is generated geometry; extend `GumFigmaIconRipper` (which
  stays a Windows-only offline utility) to also emit an Avalonia resource file with the same
  `GumIconKind` keys. No hand-porting.
- **Third-party replacements, one decision each:**

  | WPF package | Used for | Replacement |
  |---|---|---|
  | `MaterialDesignThemes` | style base, a few controls | Fluent base + FRB dictionaries (above) |
  | `ControlzEx` | custom window chrome, caption buttons | Avalonia `ExtendClientAreaToDecorationsHint` + custom title bar; standard chrome is acceptable until parity polish |
  | `FluentIcons.Wpf` | Fluent icon glyphs | `FluentIcons.Avalonia` (same icon enum, same author) |
  | `PixiEditor.ColorPicker` | color picker in `ColorDisplay`/swatch | an Avalonia color picker (`Avalonia.Controls.ColorPicker` in 11.x) wrapped behind the existing `ColorDisplay` VM |
  | `SharpVectors` | SVG rendering in WPF views | `Svg.Skia`'s Avalonia control (already a dependency for the Skia plugin) |
  | `Xceed.Wpf.AvalonDock` (DLL refs) | vestigial utility types in `Dialog.cs` | delete |
  | `Microsoft.AppCenter.*` | analytics + crash reporting | drop, or a cross-platform replacement; **owner decision**, tracked in the plan README |

- **App scale** (`AppScale.cs`, `IAppScaleProvider`) maps to Avalonia's `RenderScaling` plus a
  user scale factor applied as a `LayoutTransform` on the root, same semantics as today.

## Scope

**In:** theme dictionaries, theme switching, accent colors, app scale, icon resource generation,
window chrome, the replacements above, the theme preview image, dark/light parity screenshot
checklist per panel.

**Out:** new themes; restyling the WPF tool; any change to what `IThemingService` exposes
without a WPF-side change first.

## Tasks

1. Port `Frb.Brushes.*`, `Frb.Accents`, `Frb.Theming` to `ThemeDictionaries`; Avalonia `IThemingService`.
2. Re-base `Frb.Styles*`, `Frb.Buttons`, `Frb.TreeView`, `MainPanelControl.Styles` on Fluent.
3. Extend `GumFigmaIconRipper` to emit the Avalonia icon resource; wire `GumIconKind`.
4. Replace each third-party package per the table; delete AvalonDock references from `Gum.csproj`
   as boyscout work if the vestigial types are dead.
5. App scale; theme preview; theming dialog on the Avalonia head.
6. Custom window chrome parity (last; standard chrome ships in the preview channel if needed).
7. Dark/light screenshot pass over every panel on all three OSes.

## Dependencies

Needs phase 30. Independent of 50–80, but 80's views look wrong until this lands; sequence the
brush/theme port early and the chrome late.

## Risks

- Fluent's default control metrics differ from MaterialDesign's; parity screenshots will show
  spacing drift. Accept small drift; fix egregious cases in the FRB dictionaries.
- Font rendering differs per OS; the tool's UI font stack needs fallbacks on macOS/Linux.

## Done when

- [ ] Light and dark themes switch at runtime with the FRB palette on all three OSes.
- [ ] All icons render from the generated resource; no `FluentIcons.Wpf`, `SharpVectors`,
      `PixiEditor`, `ControlzEx`, `MaterialDesignThemes`, or AvalonDock in the Avalonia graph.
- [ ] AppCenter decision recorded and applied.
