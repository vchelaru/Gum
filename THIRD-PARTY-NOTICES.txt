--------------------------------------------------------------------------------
HOW TO ADD A NEW COMPONENT
--------------------------------------------------------------------------------
When you add a dependency that is redistributed with the Gum tool (a NuGet
package or vendored DLL whose managed assembly or native binary ends up in the
release package), add it to the appropriate license group below and list its
NuGet package ID(s) on the entry's "NuGet:" line. If it introduces a license
not already represented, add that license's full text (or a canonical reference
for long, well-known licenses) to the "LICENSE TEXTS" section.

Use this per-component shape inside a license group:

    <name> — <copyright holder>
        <project / repo URL>
        NuGet: <package id>, <package id>, <Prefix>.*
        [optional note, e.g. native binary vs. managed wrapper]

ThirdPartyNoticesCoverageTests (Gum.Avalonia.Tests, for Gum.deps.json) and
the matching test in Gum.Cli.Tests (for gumcli.deps.json) fail when a package
in the shipped dependency graph is not named on a "NuGet:" line. Microsoft.*,
System.* and runtime.* packages are covered by the .NET entry and are not
checked individually.

Note the distinction between a package's declared NuGet license and what it
actually carries: a managed wrapper may be MIT while the native binary it
bundles is under a different license. Credit the binary's real license, not
just the wrapper's nuspec value. Examples below: SkiaSharp (MIT wrapper /
BSD-3 native Skia), FreeTypeSharp (MIT wrapper / FreeType-License native
FreeType), ShadowDusk.HLSL (MIT wrapper / LGPL-2.1 native vkd3d-shader).
